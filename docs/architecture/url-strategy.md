# URL strategy

## Rules

1. **Canonical host is `https://justicecenterid.com`.** One host, HTTPS only. The `www`
   subdomain 301-redirects to the apex at the CDN level (see
   [netlify-strategy.md](../deployment/netlify-strategy.md)). Only the apex form appears in
   canonical tags, the sitemap, structured data, and the feed.
2. **Lowercase, hyphenated, ASCII.** No underscores, no camelCase, no percent-encoded
   characters, no diacritics in slugs. Institution names that carry diacritics keep them in
   the page title, not in the URL.
3. **No trailing slash.** `trailingSlash` is left at its default (`false`). Netlify's
   `pretty_urls` handling is disabled so that the framework's canonical form is the only
   form served.
4. **No file extensions**, except for machine-readable endpoints (`/sitemap.xml`,
   `/feed.xml`, `/llms.txt`, `/robots.txt`).
5. **No dates in paths.** Entities are maintained, not published on a date. Freshness is
   expressed in page metadata (`dateModified`, review date), not in the URL.
6. **No pagination in this phase.** Hub pages are complete lists. When a hub exceeds a
   reasonable single-page length, the resolution is a narrower child hub with a meaningful
   slug (`/institutions/police-organisations`), not `?page=2`. Paginated URLs would each need
   their own canonical treatment and add crawl surface for no reader benefit.
7. **No query parameters affect content.** Every indexable URL is a clean path. There are no
   filter, sort, or session parameters, so there are no parameter-driven duplicates.
8. **Slugs are permanent.** A slug is part of the published contract. If a topic is renamed,
   the slug stays and only the title changes. If a slug genuinely must change, a permanent
   redirect is added to `netlify.toml` in the same commit and never removed.
9. **The route registry is the single source of truth.** `src/lib/routes.ts` enumerates every
   route. The sitemap, the breadcrumb builder, the internal-link validator, and the exported
   output verifier all read from it. A route that exists as a file but not in the registry
   fails validation, and vice versa.

## Reserved namespaces

These root segments are reserved now so that future work cannot collide with an existing
page or force a redirect:

`api`, `admin`, `search`, `assets`, `static`, `_next`, `data`, `feed`, `rss`, `sitemap`,
`tags`, `topics`, `authors`, `news`, `blog`.

`blog`, `news`, `tags`, and `authors` are reserved specifically so they stay unused — the
site is not organised that way, and reserving them prevents a later drift back into
article-first architecture.

## Planned future patterns

Documented now so slugs stay compatible. None of these routes exist yet, and none appear in
the sitemap.

| Pattern | Example | Notes |
| --- | --- | --- |
| Country hub | `/countries/ie` | Segment is the lowercase ISO 3166-1 alpha-2 code, not a name, so it is stable across renaming and unambiguous across languages. The page title carries the country name. |
| Country module | `/countries/ie/courts` | Module slugs are fixed and shared across countries: `justice-system`, `law-enforcement`, `courts`, `prosecution`, `corrections`, `border-and-customs`, `history`, `oversight`, `training`, `sources`. A module route exists only where that module has been researched — never as a stub. |
| Institution type | `/institutions/gendarmerie` | Institution *types*, not named agencies. |
| Named institution | `/institutions/{type}/{institution}` | Deferred; requires per-institution sourcing. |
| Profession | `/professions/detective` | |
| Forensic discipline | `/forensics/disciplines/{slug}` | Nested to keep the section root readable and to separate disciplines from concept guides. |
| Historical period | `/history/{period-slug}` | |
| Comparison | `/comparisons/{a}-vs-{b}` | Only where the comparison is a genuine institutional question, and only with an explicit equivalence claim and sources on both sides. |
| Glossary term detail | `/glossary/{term}` | Only if a term outgrows its glossary entry. Terms are addressable today via fragment (`/glossary#due-process`). |

### Rejected patterns

| Pattern | Why rejected |
| --- | --- |
| `/countries/ireland` | Country names are not stable identifiers, vary by language, and are politically contested in some cases. ISO codes are neither. |
| `/guides/{slug}` (flat) | Discards topical clustering; a guide's section is part of its meaning and part of its internal-link graph. |
| `/{section}/guides/{slug}` | Adds a segment that carries no information for the reader. |
| `/2026/07/what-is-due-process` | Date-based paths imply an article that expires. |
| `?country=ie&topic=courts` | Parameter-driven content creates duplicate-canonical risk and is not crawlable as a hub. |

## Canonical, indexing, and duplication control

- Every page emits exactly one canonical URL, built by `src/lib/metadata.ts` from the route
  registry and the canonical host. Canonicals are never hand-written in a page.
- Duplicate canonical URLs across two routes are a test failure
  (`tests/content/routes.test.ts`).
- Pages whose entity status is not `published` are excluded from the build entirely, so a
  draft cannot leak into the sitemap or be reached at a URL.
- `404.html` carries `noindex`. Every other route is indexable; there is no thin page needing
  suppression, which is itself the intended outcome of the scaling model.
- The sitemap contains only routes that exist in the exported output. `verify:output` asserts
  this in both directions.
